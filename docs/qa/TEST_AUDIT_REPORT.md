# Resort Empire automated test suite audit

**Audit date** 2026-11-24

**Revision** `cb6303dbeae72663398d9070f6f81bd451dac475` on `main`

## Summary

Unity discovered and passed **326 test cases** across **290 test methods** in **30 test-bearing C# files**. The suite includes **318 EditMode cases** and **8 PlayMode cases**. The first priorities are a pointer-driven gameplay smoke test in the production Resort scene, explicit coverage of arrival-closed Worker transfers, and save continuation checks that compare a restored wave with an uninterrupted control.

The audit read each test body and its relevant fixture setup, helpers and production path. The inventory records each leaf case's target, protected behavior, reason for classification, recommended action, dependencies, isolation and execution verdict. `KEEP` means the case protects a distinct or worthwhile behavior at its level. `IMPROVE` means the scenario has value and needs a tighter oracle, clearer scope or stronger isolation. `MERGE_CANDIDATE` means an overlapping check can be consolidated if its unique input or assertion is preserved. `REPLACE_CANDIDATE` means the intended behavior merits a test through a connected entry point. `REMOVE_CANDIDATE` is reserved for cases with no distinct assertion or valuable intent. `BLOCKED` is reserved for cases that cannot be reviewed meaningfully because an essential dependency is unavailable. Execution results are recorded independently. The audit uses source and execution evidence with no mutation testing or code coverage measurement.

## Ten most important findings

1. **The suite protects the eight-wave model and façade.** `FullEightWaveLoopIncludesRushAndStopsAfterEight` asserts all eight result IDs, 51 served in Wave 2 and terminal rejection of Wave 9. `FacadeCompletesAllWavesAndPublishesCanonicalResults` adds exactly eight result and wallet publications, and rejects immediate repeat claims. The pressure-trace test adds feedback assertions. Those loops use `EconomyTestFixtures.Config()`. A live, purchased 3 → 4 → 5-service campaign with production tuning, exact need totals and final state is still missing. [Economy progression](../../Assets/_ResortEmpire/Tests/Gameplay/EditMode/EconomyProgressionTests.cs#L451) · [Facade loop](../../Assets/_ResortEmpire/Tests/Gameplay/EditMode/EconomyUnityIntegrationTests.cs#L65) · [Warning trace](../../Assets/_ResortEmpire/Tests/Gameplay/EditMode/BottleneckDetectionTimingTests.cs#L187)
2. **PlayMode covers the real menu and navigation, with the Resort gameplay controls largely outside that boundary.** The eight coroutine tests exercise scene loads, one-session locking, menu pointer hit tests, corrupt saves, confirmation and synthetic screen sizes. S2→S3 cases call a coordinator, and S4/S5/S9 cases call commands or inspect window state. A non-raycastable need card, a stale listener or an inaccessible claim button can escape those checks. The historical QA report documents this failure mode and the current `WaveNeedCard.prefab` has its root graphic enabled for raycasts. The remaining gap is an automated production-scene input path. [PlayMode fixture](../../Assets/_ResortEmpire/Tests/Gameplay/PlayMode/MainMenuNavigationTests.cs) · [S2/S3 tests](../../Assets/_ResortEmpire/Tests/Gameplay/EditMode/WorkerAllocationFromWaveNeedsTests.cs) · [Historical raycast finding](PrototypeLoopVerification.md#defects-found) · [Current card prefab](../../Assets/_ResortEmpire/Prefabs/UI/WaveNeedCard.prefab#L2430)
3. **One test's claimed drain transfer occurs during arrivals.** `ActiveWorkerReassignmentRemainsAvailableThroughQueueDrain` moves the Worker at 1.5 seconds in a four-second arrival window. The suite does check post-closure transfer in a boost scenario and tests source slowdown and destination speedup at seat level. An ordinary post-closure transfer should directly verify both occupied seats and unchanged wave demand. [Named drain test](../../Assets/_ResortEmpire/Tests/Gameplay/EditMode/WaveManagerTests.cs#L209) · [Boosted drain transfer](../../Assets/_ResortEmpire/Tests/Gameplay/EditMode/EnergyBoostTests.cs#L37) · [Seat utilization tests](../../Assets/_ResortEmpire/Tests/Gameplay/EditMode/ServiceSlotRuntimeTests.cs#L41)
4. **Boost-aware restoration is real and narrowly exercised.** The JSON round trip verifies stored Energy, 11 seconds of remaining boost, dismissal, per-unit timing/progress, one-use allowance and 51 completions. A bootstrap case verifies explicit Resume. There is no paired restore-versus-uninterrupted comparison through pre-rush arrivals, in-rush partial release, post-expiry drain and completion. Current `CanSaveActiveWave` requires a used boost. Unboosted relaunch tests intentionally verify pre-wave fallback. The team architecture reference calls for frozen active-wave resume, while the checked-in Sudden Rush behavior documents the fallback. Confirm the intended product rule before writing a broader acceptance case. [JSON fixture](../../Assets/_ResortEmpire/Tests/Gameplay/EditMode/EnergyBoostTests.cs#L138) · [Save policy](../../Assets/_ResortEmpire/Scripts/Progression/ResortProgressionRuntime.cs#L135) · [Sudden Rush save behavior](../gameplay/SuddenRush.md#save-behavior) · [Team persistence guidance](../../.agents/skills/resort-empire-team-development/references/architecture-and-persistence.md)
5. **Duplicate reward coverage is strong at runtime and disk level, with one silent assertion.** Cases protect wrong IDs, immediate replay, reopened JSON, overflow, failed write and retry. `ReentrantClaimAndThrowingUiListenerCannotDuplicateOrUndoCommit` places an NUnit assertion inside a `ResourcesChanged` callback. `Publish` catches that exception, and a later deliberate listener exception can overwrite its message. Final balance and claimed-state checks still run. An external assertion on the nested return and event counts is needed. [Claim and re-entrancy tests](../../Assets/_ResortEmpire/Tests/Gameplay/EditMode/EconomyProgressionTests.cs#L268) · [JSON replay](../../Assets/_ResortEmpire/Tests/Gameplay/EditMode/EconomyUnityIntegrationTests.cs#L124) · [Publish](../../Assets/_ResortEmpire/Scripts/Progression/ResortProgressionRuntime.cs#L412)

In contrast, `DemandConservationAndCompletionRecordsRemainConsistent` can pass on empty collections, `PauseFreezesClockArrivalsAndService` observes seat count rather than normalized progress, and the bottleneck fixture has unbounded `while` loops that can hang the runner on a stuck wave. The PlayMode navigation tests exercise production input routing and scene loading where EditMode uses a fake host.

No case received a removal recommendation. Consolidation and replacement candidates retain their current status until equivalent coverage is demonstrated. Start by strengthening the high-risk entry points and assertions above.
